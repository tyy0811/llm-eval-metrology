### `fetch_date` gets a committed source, by offline schema migration

`CANONICAL_FETCH_DATE = "2026-07-29"` is a literal in `run.py`, and the manifest carries no date
field: confirmed by reading both. Validating the card against a second literal in `report.py`
would create the duplicate this check exists to catch.

**No network fetch.** A fetch run today cannot establish the historical date `2026-07-29`; it can
only confirm that the pinned bytes are still reachable today. Re-fetching to obtain a date the
fetch cannot know would be ceremony that risks the committed digests for no evidence. This is a
schema migration performed offline:

1. Add `"fetch_date": "2026-07-29"` to `manifests/upstream_digests.json`.
2. **Prove the migration is additive**: a control parses the committed manifest, removes
   `fetch_date`, and asserts the result equals the pre-migration parsed manifest exactly, so the
   field addition provably changed nothing else.
3. Delete `CANONICAL_FETCH_DATE` from `run.py`, with a test asserting the name is gone so the
   literal cannot return.
4. `run.py` and `validate_card_set` both read the date from the manifest.
5. Validate it as a canonical, real calendar date in `YYYY-MM-DD` form, parsed with
   `datetime.date.fromisoformat` and required to round-trip to the same string, so `2026-13-01`
   and `2026-7-29` both fail.

`fetch.py` gains `--bootstrap`, which requires an explicit `--fetch-date` and refuses to invent
one. A normal run preserves the committed date rather than stamping today's, which keeps the
manifest free of ambient state per D0.9 item 6.

## 3. `validate_card_set`: total, declarative, structural

A declarative table maps every leaf of every card to exactly one rule. Enforcement is
bidirectional and structural, not a scalar-leaf walk: a walk alone lets an unknown empty object or
a nonscalar addition pass unseen.

**Structural requirements.** Exact top-level keys `{family, pairs}`. At every level, the object's
key set must equal the rule set's key set exactly, so an added key fails whether or not it holds a
scalar and an empty object or list fails unless a rule declares it. Lists are validated by exact
length with **indexed** rules. Exactly one rule matches each leaf; a leaf with no rule fails, a
rule whose card path does not exist fails, and two rules matching one path fail. Comparison is by
exact JSON type and value, never by tolerance and never by `==` alone, since `True == 1` and
`1 == 1.0` in Python.

**Four rule kinds.**

- **SOURCE**: equals the value at a named path in `results.json`, `aggregates.json`, or the
  manifest. `separability_basis` is a SOURCE rule against `results:primary.separability_basis`,
  verified equal in the committed pair, and not the prose rule the first draft made it.
- **CONSTANT**: equals an exact literal the engine registers (`TWO_SIDED_CONVENTION`, `RULE_HOLM`,
  `CARD_PAIR`, `CARD_FAMILY`, `"holm"`, `"adjacent_pairs"`), and exact literals for invariant
  prose: `claim_type`, `scope.comparisons`, `scope.excludes`, `definitions.separable`,
  `observed.note`, `limit.floor_label`, `limit.observed_extreme_label`.
- **PROSE_TEMPLATE**: for a generated sentence, a declared template of literal text plus
  source-qualified placeholders. The validator formats the template from sources and requires
  **exact string equality**, so both the wording and the figure are checked.
- **DERIVED**: equals a named pure function of sources. Used for the malformed-field disclosure
  text of section 4.

**Why PROSE_FIGURES is gone.** Measured against the committed card: of the nine prose fields the
first draft assigned to it, **eight contain no numerals at all** and only `limit.inference`
contains one. A numeral-only rule would have accepted arbitrary replacement prose in eight fields,
and in the ninth would have accepted a sentence whose conclusion was reversed while the numeral
stayed. That is not a weaker version of totality; it is an absence of it.

`limit.inference` is the one PROSE_TEMPLATE today. Its templates are declared per branch together
with the condition selecting the branch, and both the selection and the formatted string are
checked. The cost is that an engine wording change must be mirrored in the crosswalk, which is
the intent: a load-bearing inference sentence should not be rewordable without an explicit
decision.

**Lists.** `conditionality`, `disclosure.applies_to_headline`, `disclosure.applies_to_secondary`,
and `provenance.deviations` are validated by exact length, exact order, and exact values.
`applies_to_headline` must be empty, which is D1.11 at the card boundary.

**Indexed structural rules.** `ruler.split[0]` maps to the record's `n10` and `ruler.split[1]` to
`n01`, as two rules rather than one list-valued rule. The committed card reads `[36, 29]` against
`n01 = 29, n10 = 36`, so a reversed mapping would render the ruler's edge favouring the wrong
system with every individual number still correct.

### Coverage map

**The inventory is computed, not asserted.** The committed cards carry 33 scalar leaves on the
family card and 36 on a pair card. Checking revision 2's named rules against that inventory found
**six leaves with no rule**, so its "exactly one rule per leaf" claim was not yet true:
`comparison.name`, `criterion.statistic`, `test.statistic`, `ruler.requirement_basis`,
`ruler.threshold_basis`, and `mde.alpha_basis`. Their rules:

- `comparison.name` is SOURCE against the matched record's `name`. The wrapper's key equality
  from the section below stays a **structural** guard and is not a second rule for this leaf, so
  the one-rule-per-leaf invariant holds.
- `criterion.statistic` and `test.statistic` share **one** registered statistic constant, so the
  family card and a pair card cannot name different statistics for the same procedure.
- `ruler.requirement_basis`, `ruler.threshold_basis`, and `mde.alpha_basis` are exact CONSTANT
  rules. These three carry the load D1.7 and D2.6 put on them, naming which threshold a number was
  computed at, so each gets a mutation control: a card that swapped
  `mde.alpha_basis` for the family-correction wording would be numerically correct and still lie
  about which alpha produced its MDE.

The totality test regenerates this inventory from the committed cards at test time rather than
pinning a count, in both directions, exactly as the number-format registry does.

Family SOURCE rules resolve against `primary`, `configuration`, and `secondary.non_tied_family`:
`headline.separable_count`, `headline.family_size`, `observed.resolved_count`, `criterion.alpha`,
`criterion.threshold`, `limit.first_rejection_gap_floor`, `limit.observed_extreme`,
`progressive_disclosure.secondary_family_size`, `progressive_disclosure.secondary_family_floor`,
and `separability_basis`. The eleven `family_finding` keys, enumerated from the artifact, are
`claim_type`, `conditionality`, `criterion`, `definitions`, `disclosure`, `headline`, `limit`,
`observed`, `progressive_disclosure`, `scope`, and `separability_basis`; the rule set covers every
leaf beneath all eleven.

Each pair card resolves against the `pairs[]` record whose `name` equals its `comparison.name`:
`system_a`, `system_b`, `test.p_value`, `test.adjusted_p_value`, `verdict`,
`ruler.observed_disagreements` against `n_discordant`, `ruler.observed_net_edge` against
`net_edge`, `ruler.required_net_edge_at_observed`, `mde.discordance_rate`, and every `mde` field
including `status`. `comparison.n_items` against `aggregates:n_items`, `comparison.instrument`
against `configuration.instrument`, `ruler.threshold` against `primary.first_critical`,
`test.alpha` against `configuration.alpha`, and `mde.alpha` and `mde.target_power` against
`mde_grid`, the registered uncorrected level and deliberately not the family threshold.

### The wrapper

Exactly one `family` card. `pairs` keys equal `illustrative_pair_names(entries)` as a set, with no

## 4. Provenance, exactly

### 4a. The manifest population, validated before anything is derived from it

Revision 2 derived provenance from the manifest without checking that the manifest describes the
analysed board. A manifest holding only the four systems named on the two illustrative cards would
have satisfied every revision rule while the family card described a twenty-system analysis. So
the population is validated first, and every requirement below holds on the committed manifest
today, measured while writing this section:

- Artifact systems equal the aggregate entries in **membership, uniqueness, and published order**,
  not as a set. Confirmed: the 20 artifact systems equal the rank-ordered aggregate systems
  exactly, with no duplicates.
- Each artifact appears exactly once.
- Each artifact URL's system component agrees with that record's `system` field. Confirmed: no
  artifact's URL disagrees with its own system.
- `board.url` embeds the same revision as `board.commit`. Confirmed equal at
  `7c4289f30aa1a1c63c2e2a25aae30c16d92b5114`.
- All artifact URLs share the expected repository and a single revision. Confirmed: one repository
  (`SWE-bench/experiments`) and one revision across all 20.
- The `source` and `secondary_source` labels are **derived from those repository identities**
  rather than compared against literals, so a card naming a repository the manifest never fetched
  fails. Confirmed derivable: the artifact repository is the artifact source and the board
  repository (`SWE-bench/swe-bench.github.io`) is the board source.
- `fetch_date` is a valid canonical calendar date per section 2.

Controls: an artifact missing, extra, duplicated, or reordered against the aggregates; an artifact
URL whose system component disagrees with its `system`; a `board.url` whose embedded revision
disagrees with `board.commit`; an artifact URL on an unexpected repository.

### 4b. The card provenance rules

- Exact `source`, `secondary_source`, `secondary_revision`, and `fetch_date` on every card, with
  `fetch_date` read from the manifest per section 2.
- `deviations` validated as an exact list: no missing, extra, reordered, or duplicate entry.
- **One artifact revision.** Every `artifacts[].url` must resolve to a single revision before that
  revision may be used as the family card's `secondary_revision`. All 20 currently agree; a mixed
  manifest must fail rather than silently taking the first.
- Each pair card's `pinned_revision` must agree with the manifest records for **both** of its
  systems, not one.
- The family card's `pinned_revision` equals `board.commit`; pair cards carry
  `secondary_source` and `secondary_revision` as null.
- **Malformed-field disclosures are derived, not matched loosely.** For each selected pair, the
  expected disclosure set is computed from that pair's aggregate entries: an entry whose
  `checked_is_malformed` is true contributes a disclosure naming its rank and quoting
  `checked_raw` exactly. A pair whose entries carry no malformed field must carry no such
  disclosure. This is what makes the D8 obligation checkable in both directions rather than a
  substring search for the word `checked`.

## 5. `render_pair_table`, after an approved reference

**D1.3 order, and why it binds here.** The approved reference records that the nineteen-row table
was deferred until its row schema existed, and `card.css` contains **zero** table styling:
confirmed by reading both. Writing the renderer first and blessing its snapshot would make the
fixture record whatever the renderer emitted, which is exactly the failure D1.3 exists to prevent
and which D2.8 credits for catching a heading regression. So:

1. Build a standalone illustrative table reference in the card visual language, with clearly
   labelled illustrative numbers per the fixture convention.
2. Jane approves it.
3. Commit it, **before** any renderer code exists.
4. Implement `render_pair_table` and its snapshots against the approved reference.

```python
render_pair_table(columns, rows, *, heading, disclosure) -> str
```

Emits semantic `table`, `thead`, `tbody`, and a `caption` carrying the heading, inside a container
with horizontal overflow so a narrow screen scrolls the table rather than the page. Escapes every
heading, disclosure, header, and cell through `html.escape`. Rejects duplicate column names and
any row whose width differs from the column count.

Rows come from `reporting.findings_pair_rows`, already rendered. The README markdown table and the
card HTML table are two renderings of **one** projection, so the surfaces cannot disagree about a
pair. The disclosure states that D4 qualifies the observed-discordance and p-value columns, while
pair identity and the resolved-count gap derive from published aggregates.

## 6. `--write` is a complete preflight

Before the first byte: parse all inputs; `validate_sources`; validate the card-set wrapper;
`validate_card` on every card; `validate_card_set`; then build the CSV text, the README splice,
and the HTML document in full. Only then does writing begin.

Writes stay per-file atomic. Stated as the residual limit: a filesystem failure between the second
and third replace can still leave the three artifacts at different generations, and the next
`--check` reports it.

## 7. `cards.html` stays outside prose-check

Tokenizing HTML would drag in tag attributes, CSS, and hex colours for no gain. `cards.html` is
covered instead by five mechanisms, recorded in the checker's docstring so the exclusion is
visible: total semantic cross-validation of every card leaf, `validate_card` on every card, the
shared rendered table rows tying it to the README table, committed byte-drift checking, and the
renderer snapshots. Only because the crosswalk is total is that coverage accurately called
stronger than membership.

## 8. Tests and negative controls

Each shown red before its guard exists.

**Structure and totality.** Unmapped leaves of every JSON type in turn: string, number, boolean,
and null. An unknown empty object and an unknown empty list. A missing and an extra list element.
A dead rule whose card path does not exist. Two rules matching one path. A boolean stored where a
count belongs, failing on exact type.

**Card set and selection.** Missing family card; extra pair card; a pair key absent from
`illustrative_pair_names`; a card filed under a key disagreeing with its own `comparison.name`.
Document order asserted as family, table, first-published pair, widest-gap pair, against
`illustrative_pair_names` and not dictionary order.

**Values.** `ruler.split` reversed to `[n01, n10]`; a changed `required_net_edge_at_observed`;
each `mde` field in turn; `test.statistic`, `convention`, and `decision_rule`; a stale numeral in
`limit.inference`; and **an inference whose conclusion is reversed while its numeral is
retained**, which the first draft's rule would have accepted.

**Manifest population.** An artifact missing, extra, duplicated, or reordered against the
aggregate entries; an artifact URL whose system component disagrees with its `system` field; a
`board.url` revision disagreeing with `board.commit`; an artifact URL on an unexpected repository;
a `fetch_date` that is not a canonical calendar date (`2026-13-01` and `2026-7-29` both fail);
and the additive-migration control, which removes `fetch_date` from the committed manifest and
asserts the remainder equals the pre-migration parsed manifest exactly.

**The six newly mapped leaves.** A mutated `comparison.name`; `criterion.statistic` and
`test.statistic` set to different values; and each of `ruler.requirement_basis`,
`ruler.threshold_basis`, and `mde.alpha_basis` mutated in turn, including the case where
`mde.alpha_basis` is swapped for the family-correction wording while every number stays correct.

**Provenance.** D4 removed from a pair card; D4 duplicated in a deviations list; D4 moved into
`applies_to_headline`; deviations reordered; a wrong `source`; a wrong `fetch_date`; a mixed
revision manifest; a pair revision agreeing with one of its two systems but not the other; the
malformed disclosure altered, dropped, or added to a pair whose entries carry no malformed field.

**Table renderer.** Unequal row width and duplicate columns raise. A cell containing
`<script>alert(1)</script>` renders escaped and executes nothing. The HTML table parses to
**exactly nineteen** data rows, and its header and every row equal the markdown table's cell for
cell, compared with `html.parser.HTMLParser` and asserted on full equality so a truncating
comparison cannot pass.

**Document and preflight.** A hand-edited `cards.html` fails drift; rendering twice is
byte-identical; `EQUIVALENT` appears nowhere. The preflight control prepopulates the README, the
CSV, and the HTML with **distinct sentinel bytes**, triggers a late semantic-validation failure
through the live `--write` entry point, and asserts all three files remain byte-identical to their
sentinels.
