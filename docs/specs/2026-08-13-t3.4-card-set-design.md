## 1. Scope

In scope: the rendered card document, the shared table renderer, the D8 selection rule moved to
one shared home, `validate_card_set`, the `report.py` preflight, and the make and CI wiring that
already covers `report-check`.

Not in scope: `make reproduce` (T3.5), the cross-repo handoff (T3.6). No statistic changes, no
results regeneration, and no third corpus file: `cards.json` is a **validated intermediate
artifact**, never an independent source of figures.

## 2. Module layout, and two moves

`metrology/cards/` gains the table renderer. `metrology/reporting.py` gains the selection rule and
the adjacency helper, both currently living in `run.py`:

| Symbol | Home | Why it moves |
|---|---|---|
| `adjacent_pairs(entries)` | `reporting` | `illustrative_pair_names` depends on it, and it is a pure four-line projection over ranked entries |
| `illustrative_pair_names(entries)` | `reporting` | `run.py` and `report.py` must execute **one** rule; two copies of a registered selection rule is the defect D1.12 exists to prevent |
| `render_pair_table(columns, rows, *, heading, disclosure)` | `cards` | HTML ownership stays inside the card module |
| `validate_card_set(cards, results, aggregates)` | `reporting` | the crosswalk boundary of section 3 |

`run.py` imports both moved helpers rather than defining them. The rule is generic over ranked
entries, so it sits in the engine without carrying experiment policy: what is registered in D8 is
the *choice to apply* it to Experiment 1, which stays in `run.py` and `report.py`.

Pair cards render in `illustrative_pair_names` order, **never** `cards.json` dictionary order, so
the document order is the registered order rather than an artifact of serialization.

## 3. `validate_card_set`: total, declarative, both directions

The crosswalk is a declarative table mapping every scalar leaf of a card to exactly one source.
Totality is enforced in both directions: a card leaf with no rule fails, and a rule whose card
path does not exist fails. Comparison is by exact JSON type and value, never by tolerance and
never by `==` alone, since `True == 1` and `1 == 1.0` in Python and a card that stored a boolean
where a count belongs would otherwise pass.

Four rule kinds cover every leaf:

- **SOURCE**: equals the value at a named path in `results.json` or `aggregates.json`.
- **CONSTANT**: equals a literal the engine registers (`TWO_SIDED_CONVENTION`, `RULE_HOLM`,
  `CARD_PAIR`, `CARD_FAMILY`, `"holm"`, `"adjacent_pairs"`).
- **DERIVED**: equals a named pure function of sources. Exactly one rule is derived today:
  `ruler.split` must equal `[n10, n01]` **in that order**. The committed card reads `[36, 29]`
  against `n01 = 29, n10 = 36`, so a reversed mapping would render the ruler's edge favouring the
  wrong system while every number on the card stayed individually correct.
- **PROSE_FIGURES**: for a generated sentence (`limit.inference`, `observed.note`,
  `definitions.separable`, the `_basis` and `_label` strings), every numeral inside the string
  must equal the registry rendering of a declared source path. This keeps a stale inference
  sentence from surviving a corpus change without reconstructing the builder, which would repeat
  analysis inside the reporting layer.

### The family rules

`headline.separable_count`, `headline.family_size`, `observed.resolved_count`,
`criterion.alpha`, `criterion.threshold`, `limit.first_rejection_gap_floor`,
`limit.observed_extreme`, `progressive_disclosure.secondary_family_size`, and
`progressive_disclosure.secondary_family_floor` are SOURCE rules against `primary`,
`configuration`, and `secondary.non_tied_family`. `criterion.statistic`, `criterion.convention`,
`criterion.correction`, `observed.decision_rule`, `headline.unit`, and `card_kind` are CONSTANT.
`limit.inference`, `limit.floor_label`, `limit.observed_extreme_label`, `observed.note`,
`definitions.separable`, `claim_type`, `separability_basis`, `scope.comparisons`,
`scope.excludes`, and each `conditionality` entry are PROSE_FIGURES or CONSTANT. Enumerated from
the committed card rather than from memory: the eleven `family_finding` keys are `claim_type`,
`conditionality`, `criterion`, `definitions`, `disclosure`, `headline`, `limit`, `observed`,
`progressive_disclosure`, `scope`, and `separability_basis`, and the crosswalk covers every scalar
beneath all eleven. `disclosure.applies_to_headline` must be **empty** and
`disclosure.applies_to_secondary` must contain the D4 string, which is D1.11 enforced at the card
boundary.

### The pair rules

Each pair card resolves against the `results.json` `pairs[]` record whose `name` equals the card's
`comparison.name`: `system_a`, `system_b`, `test.p_value`, `test.adjusted_p_value`, `verdict`,
`ruler.observed_disagreements` against `n_discordant`, `ruler.observed_net_edge` against
`net_edge`, `ruler.required_net_edge_at_observed`, `mde.discordance_rate`, and every `mde` field
against the record's `mde` block including `status`. `comparison.n_items` is SOURCE against
`aggregates:n_items`, `comparison.instrument` against `configuration.instrument`,
`ruler.threshold` against `primary.first_critical`, `test.alpha` against `configuration.alpha`,
and `mde.alpha` and `mde.target_power` against `mde_grid`, which is the registered uncorrected
level and deliberately not the family threshold.

### The card set wrapper

Exactly one `family` card. `pairs` keys equal `illustrative_pair_names(entries)` as a set, with no
missing and no extra card, and each dictionary key equals its own card's `comparison.name`, so a
card filed under the wrong key fails rather than rendering under a false heading.

## 4. Provenance semantics, not only schema

`validate_card` already type-checks provenance. The crosswalk adds meaning:

- The D4 string appears in **every** pair card's `deviations`, and in the family card's
  `applies_to_secondary` only, never `applies_to_headline`.
- The malformed-`checked` disclosure must name the rank and quote the raw value exactly as
  `aggregates.json` records it for that entry, not merely contain the word `checked`.
- No other pair card carries that disclosure. A card that acquires it wrongly is as false as one
  that drops it.
- Every revision is checked against `manifests/upstream_digests.json`, read from the committed
  shapes rather than assumed: the family card's `pinned_revision` against `board.commit` and its
  `secondary_revision` against the revision embedded in the `artifacts[].url` prefix; each pair
  card's `pinned_revision` against that same artifact revision, with `secondary_source` and
  `secondary_revision` both null. A seal that is schema-valid and names the wrong commit is still
  a false card, and this is the one check that catches it.

## 5. `render_pair_table`

```python
render_pair_table(columns, rows, *, heading, disclosure) -> str
```

Emits semantic `table`, `thead`, `tbody`, and a `caption` carrying the heading, wrapped in a
container with horizontal overflow so a narrow screen scrolls the table rather than the page. It
escapes every heading, disclosure, header, and cell through `html.escape`, and rejects duplicate
column names and any row whose width differs from the column count.

Rows come from `reporting.findings_pair_rows`, already rendered to strings. That is the design
point: the README markdown table and the card HTML table are two renderings of **one** projection,
so the surfaces cannot disagree about a pair. A test compares the two cell for cell.

The disclosure text states that D4 qualifies the observed-discordance and p-value columns, while
pair identity and the resolved-count gap derive from published aggregates. It does not say the
caveat applies to the table.

## 6. `--write` is a complete preflight

Before the first byte is written, in order: parse all inputs; `validate_sources`; validate the
card-set wrapper; `validate_card` on every card; `validate_card_set` cross-validation; then build
the CSV text, the README splice, and the HTML document **in full**. Only then does writing begin.
Any failure leaves all three destinations untouched, which a control asserts by checking that the
README is byte-unchanged and neither the CSV nor the HTML exists.

Writes stay per-file atomic (temp file in the destination directory, then `os.replace`). Stated as
the honest residual limit: a filesystem failure between the second and third replace can still
leave the three artifacts at different generations, and the next `--check` reports it.

## 7. `cards.html` stays outside prose-check, and what covers it instead

Tokenizing HTML would drag in tag attributes, CSS, and hex colours, a large false-positive surface
for no gain. `cards.html` is covered instead by five mechanisms, recorded in the checker's
docstring so the exclusion is visible rather than silent:

1. total semantic cross-validation of every card leaf (section 3),
2. `validate_card` on every card,
3. the shared rendered table rows, which tie the card table to the README table,
4. committed byte-drift checking of the document,
5. the existing renderer snapshots.

Only after the crosswalk is total is it accurate to call this coverage stronger than membership,
so that claim appears in the spec and in DECISIONS only in that form.

## 8. Tests and negative controls

Each shown red before its guard exists.

Card set and selection: a missing family card, an extra pair card, a pair card whose key is not in
`illustrative_pair_names`, and a card filed under a key that disagrees with its own
`comparison.name` each fail. Document order is family, table, first-published pair, widest-gap
pair, asserted against `illustrative_pair_names` rather than dictionary order.

Crosswalk totality: an unmapped numeric card leaf fails; a crosswalk rule whose card path no
longer exists fails; a boolean stored where a count belongs fails on exact type.

Altered values: ruler split reversed to `[n01, n10]`; a changed `required_net_edge_at_observed`;
each `mde` field in turn; `test.statistic`, `convention`, and `decision_rule`; a stale numeral
inside `limit.inference`. Each fails.

Provenance: D4 removed from a pair card; D4 moved into `applies_to_headline`; the malformed
disclosure altered, dropped, or added to the wrong pair card; a wrong `pinned_revision` against
the manifest. Each fails.

Table renderer: unequal row width and duplicate columns raise; a cell containing
`<script>alert(1)</script>` renders escaped and executes nothing; the HTML table's cells equal the
markdown table's, compared with `html.parser.HTMLParser` rather than regex or substring matching.

Document: a hand-edited `cards.html` fails drift; rendering twice is byte-identical; `EQUIVALENT`
appears nowhere; a validation failure leaves the README byte-unchanged and neither the CSV nor the
HTML written.
