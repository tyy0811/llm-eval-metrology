# T3.5 design: `make reproduce` becomes real

Date: 2026-08-18
Status: revision 2, pending approval. **No Makefile change until this is approved.**
Task: PLAN.md T3.5

Deliverable: `make reproduce` rebuilds every committed Experiment 1 artifact from committed
inputs, fails if any byte differs, and leaves the worktree clean. CI's "reproduce must fail"
assertion is replaced by a real reproduction gate.

Binding prior decisions: D0.9 (the canonical environment and deterministic serialization), D2.5,
D2.7, D3.4 and D3.10 (the statistics this must not perturb), D3.8 (`cards.json` as a validated
intermediate with no byte check, **which this task changes**).

## 1. What reproduction means here, and what it does not

Reproduction is the claim that **the committed results are a function of the committed inputs and
the pinned environment, and of nothing else.** It is not a test that the statistics are correct;
the suite does that. It is the check that no ambient state, no local edit, and no undeclared input
contributed to a published number.

**The canonical verdict comes only from `ubuntu-24.04`, Python `3.11.15`, and the pins in
`requirements.txt`.** A local run is a development check and is never canonical evidence. Section 7
makes that mechanical rather than a matter of discipline.

## 2. The pipeline, measured from the code rather than assumed

| Stage | Command | Writes | Committed? |
|---|---|---|---|
| 1 | `fetch.py` | `derived/labels.csv`, `derived/unevaluated.json` | untracked, gitignored |
| 1 | `fetch.py` | `derived/aggregates.json` | **tracked** |
| 2 | `run.py` | `results/results.json`, `results/cards.json` | **tracked** |
| 3 | `report.py --write` | `results/pairs.csv`, `results/cards.html`, and the `README.md` block | **tracked** |

**Six tracked paths are verified: five generated artifact files plus `README.md`.** The two
gitignored derived files are rebuilt every run and must not affect the verdict.

`fetch.py` already verifies the committed digests: `compare_manifest` compares board, dataset,
every artifact in published order, and the derived checksums, raising `GateFailure` listing every
mismatch. **That verification is used, not rewritten.** The manifest is an input; `--bootstrap` is
the only thing that writes it, and `reproduce` must never pass it.

## 3. The target

```make
reproduce: check-python
	$(PYTHON) scripts/check_reproduction.py --preflight
	$(PYTHON) experiments/swebench/fetch.py
	$(PYTHON) experiments/swebench/run.py
	$(PYTHON) experiments/swebench/report.py --write
	$(PYTHON) scripts/check_reproduction.py --verify
```

**`$(PYTHON)` throughout, never a literal `python3`.** The Makefile defines `PYTHON ?= python3`
and every existing target uses it, so a literal here would let `check-python` validate one
interpreter while reproduction ran another, and the environment banner would then describe an
interpreter that did not produce the bytes.

### 3.1 The preflight, and why it comes first

`fetch.py`, `run.py` and `report.py --write` all overwrite tracked artifacts. Without a preflight,
an uncommitted edit to `results.json` is silently destroyed by stage 2 and the final check then
reports a clean tree: the run would erase the evidence of its own invalidity and report success.

So `--preflight` refuses to start when the worktree is not clean, rejecting **any** tracked
modification (staged or unstaged) and any non-ignored untracked file. It names what it found. A
developer with real work in progress is told to stash it rather than having it overwritten.

### 3.2 The verification, over the whole worktree

`--verify` examines the **entire worktree**, not a declared artifact list. A list would miss a
modified source file, a staged change, and any tracked output nobody thought to declare, which is
the enumeration failure this repository has paid for repeatedly: a guard that checks the paths its
author listed cannot see the path they did not.

It fails, naming every offender, when any of these holds:

1. `git status --porcelain` reports anything at all: tracked modification, staged change, untracked
   non-ignored file, deletion, or rename.
2. Any of the six tracked paths is missing.

It prints `git diff` for tracked changes on failure, because a byte mismatch with no diff shown is
a report that cannot be acted on.

Diffing is by git, not by a checksum list maintained in this repository. A maintained list would be
a second source of truth for a fact the object store already holds authoritatively.

## 4. What this changes about `cards.json`

D3.8 records that `cards.json` is a validated intermediate with **no** byte check, because
`report.py` cannot regenerate it, and that `validate_card_set`'s totality stands in place of one.
After T3.5, `run.py` regenerates it under `make reproduce` and the byte check exists.

Both guards stay. The crosswalk catches a card that disagrees with its sources on any machine and
in any working tree; the byte check catches only what a full canonical rebuild produces. They fail
on different things and neither subsumes the other. The DECISIONS entry records the change to
D3.8's stated limitation rather than leaving it reading as still true.

## 5. Network, and the failure modes the code does not yet distinguish

T3.5 is the first task permitted to run `fetch.py` against upstream, and that prohibition ends here
by design. **The digests are the safety net, not the network.**

**`fetch_bytes` today handles one case and lets the rest escape as raw exceptions.** Measured by
reading it: it catches `urllib.error.HTTPError`, returns `None` for 404, and re-raises every other
HTTP status. A timeout, a refused connection, and a DNS failure raise `URLError` or
`socket.timeout` and are not caught at all. So a rate limit and an outage both surface today as an
unhandled traceback, which is indistinguishable to a reader from a repository defect.

T3.5 adds four distinguishable outcomes, each reported with its own message and each tested:

| Outcome | Cause | What it means |
|---|---|---|
| **Absent** | HTTP 404 | The pinned object is gone. Today's `None` return; unchanged. |
| **Rate limited** | HTTP 429 | Infrastructure. Retry later; not a reproduction failure. |
| **Unavailable** | timeout, refused connection, DNS failure, HTTP 5xx | Infrastructure. Not a reproduction failure. |
| **Moved** | `compare_manifest` mismatch | **A finding.** Upstream changed under a pinned revision. |

The first three are infrastructure and must not read as "the committed results do not reproduce".
The fourth is a fact about the world worth recording, and **the manifest must not be
re-bootstrapped to make it go away**.

Changing `fetch_bytes`' failure behaviour touches existing tests that patch it, including the
no-network guards added in T3.4. Those patches must keep working; the plan must check them rather
than assume.

**Not vendoring upstream, and why.** Vendoring the artifacts into the repository would make the
reproduction claim circular: it would prove the pipeline is deterministic while proving nothing
about whether the committed results came from the upstream data they claim to. The cost of not
vendoring is that reproduction depends on a live network, which section 6's classification makes
legible instead of confusing.

## 6. The CI gate

The "reproduce is a loud failure at this phase" step is deleted and replaced by:

```yaml
      - name: reproduce
        run: make reproduce PYTHON=python

      - name: worktree is clean after reproduction
        if: ${{ always() }}
        run: |
          if [ -n "$(git status --porcelain)" ]; then
            git status --porcelain
            git diff
            exit 1
          fi
```

**`if: ${{ always() }}` is required**, not decorative. Without it GitHub skips the step when
`make reproduce` fails, which is exactly the case where its diff is wanted, and the promise to
print one would be unkept in the only situation that needs it.

The second step is deliberately redundant with `check_reproduction.py`. The script can be wrong;
`git status` in the job cannot be wrong in the same way, and the two failing together is worth more
than either alone. The checker gives artifact-specific diagnostics; CI gives a repository-wide
backstop that shares no code with it.

**CI is the only place a reproduction verdict is established.** The job already pins the runner
image and the patch version and records the environment.

## 7. The environment banner, and what establishes canonical

Two modes, because a warning nobody must act on and a gate that must hold are different things.

- **Local, the default.** The checker prints the interpreter, its exact version, and the platform,
  and **always states that this run is a development check and not canonical evidence**. It does
  not fail on a non-canonical environment, per D0.9: local runs are meant to be useful. The banner
  is unconditional, so it cannot rot into something that only appears in cases nobody hits.
- **Canonical, `--canonical`, passed by CI.** The checker **fails** unless the interpreter is
  exactly Python 3.11.15.

The checker cannot establish the runner image: `platform.system() == "Linux"` does not distinguish
`ubuntu-24.04` from anything else Linux, and an OS-release string read at runtime would be one more
thing to keep true. **The runner label is pinned in the workflow and asserted by a test over the
workflow file**, which is where that fact actually lives. The checker verifies the interpreter; the
workflow pins the image; a test pins the workflow.

## 8. Tests

Every control shown failing before its guard exists.

**The preflight.**
- A tracked modification, a staged change, and an untracked non-ignored file each refuse to start,
  and each is named.
- A gitignored file does not block the start.
- The preflight refusing means no writer ran: assert the artifacts are untouched afterwards.

**The verification.**
- For each of the six tracked paths, dirty exactly that one and assert the checker names it and
  exits non-zero.
- A modified **source** file fails it, which a declared-artifact list would have missed.
- A staged-but-uncommitted change fails it.
- An untracked non-ignored file fails it.
- A gitignored file does not fail it: `labels.csv` and `unevaluated.json` are rebuilt every run.
- A missing tracked artifact fails, distinctly from an unchanged one.
- The exit code is the gate, asserted directly rather than by parsing output.

**The environment.**
- The non-canonical banner appears on every local run, asserted on the canonical interpreter too so
  it cannot become conditional.
- `--canonical` fails on a non-3.11.15 interpreter and passes on 3.11.15.
- A test over `.github/workflows/ci.yml` asserts `runs-on: ubuntu-24.04` and `python-version:
  "3.11.15"`, so the two halves of the canonical claim are both pinned somewhere a test can see.

**The network classification.** Each of 404, 429, timeout, connection refused, and HTTP 5xx maps to
its own outcome and message, exercised against a patched transport with no real network. The
existing `fetch_bytes` patches in the T3.4 no-network guards keep working.

**The Makefile.**
- `reproduce` never passes `--bootstrap`, asserted against the Makefile text. A bootstrap inside
  reproduce would rewrite the manifest it is supposed to be checked against and turn every mismatch
  into a silent pass. **This is the highest-value control in the task.**
- Every recipe line uses `$(PYTHON)`, asserted against the Makefile text, so a literal `python3`
  cannot creep back in.
- The CI workflow contains no "reproduce must fail" assertion, so the old gate cannot survive
  alongside the new one.

Not tested here, because it cannot be: that the canonical environment produces these exact bytes.
Only CI establishes that, by running.

## 9. What gets recorded

One DECISIONS entry: reproduction is real, what the target does and in what order, the preflight
and why it precedes the writers, the whole-worktree verification rather than a declared list, the
