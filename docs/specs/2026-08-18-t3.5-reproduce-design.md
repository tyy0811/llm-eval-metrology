# T3.5 design: `make reproduce` becomes real

Date: 2026-08-18
Status: draft, pending approval. **No Makefile change until this is approved.**
Task: PLAN.md T3.5

Deliverable: `make reproduce` rebuilds every committed Experiment 1 artifact from committed
inputs, fails if any byte differs, and leaves the worktree clean. CI's "reproduce must fail"
assertion is replaced by a real reproduction gate.

Binding prior decisions: D0.9 (the canonical environment and deterministic serialization), D2.5,
D2.7, D3.4 and D3.10 (the statistics this must not perturb), D3.8 (`cards.json` as a validated
intermediate with no byte check, **which this task changes**).

## 1. What reproduction means here, and what it does not

Reproduction is the claim that **the committed results are a function of the committed inputs and
the pinned environment, and of nothing else.** It is not a test that the statistics are correct;
the suite does that. It is the check that no ambient state, no local edit, and no undeclared input
contributed to a published number.

**The canonical verdict comes only from `ubuntu-24.04`, Python `3.11.15`, and the pins in
`requirements.txt`.** A local run is a development convenience. This spec is written so that a
green local run cannot be mistaken for reproduction: the target prints the environment it ran in,
and the CI gate is the only thing that establishes byte identity. Section 6 makes that mechanical
rather than a matter of discipline.

## 2. The pipeline, measured from the code rather than assumed

| Stage | Command | Reads | Writes | Committed? |
|---|---|---|---|---|
| 1 | `fetch.py` | manifest, upstream over the network | `derived/labels.csv`, `derived/unevaluated.json` | untracked, gitignored |
| 1 | `fetch.py` | as above | `derived/aggregates.json` | **committed** |
| 2 | `run.py` | `derived/aggregates.json`, manifest | `results/results.json`, `results/cards.json` | **committed** |
| 3 | `report.py --write` | `results.json`, `aggregates.json`, `cards.json`, manifest | `results/pairs.csv`, `results/cards.html`, `README.md` block | **committed** |

Five committed artifacts must come back byte for byte: `aggregates.json`, `results.json`,
`cards.json`, `pairs.csv`, `cards.html`, plus the README block spliced in place.

`fetch.py` already verifies the committed digests itself: `compare_manifest` compares board,
dataset, every artifact in published order, and the derived checksums, and raises `GateFailure`
listing every mismatch. **The digest verification T3.5 needs already exists and must be used, not
rewritten.** The manifest is an input; `--bootstrap` is the only thing that writes it, and
`reproduce` must never pass `--bootstrap`.

## 3. The target

```
reproduce: check-python
	python3 experiments/swebench/fetch.py
	python3 experiments/swebench/run.py
	python3 experiments/swebench/report.py --write
	python3 scripts/check_reproduction.py
```

Each stage halts on failure by its own gates. The final script is what turns "the commands ran"
into "the committed artifacts are unchanged", and it is a script rather than a shell one-liner so
it can be tested.

### `scripts/check_reproduction.py`

Fails, naming every offender, when any of these holds:

1. `git diff --name-only` is non-empty for the five committed artifacts or the README.
2. `git status --porcelain` reports any untracked non-ignored file, so a stage that writes a new
   artifact nobody declared is caught rather than ignored.
3. Any expected artifact is missing.

It prints the environment it ran in, and **prints a non-canonical banner when the interpreter is
not Python 3.11.15 or the platform is not Linux**, so a developer reading a green local run cannot
mistake it for the canonical verdict. It does not fail on a non-canonical environment: local runs
are meant to be useful.

Diffing is by `git diff`, not by a checksum list maintained here. A second list of expected
checksums would be a second source of truth for the same fact, and the repository already carries
the authoritative one in its object store.

## 4. What this changes about `cards.json`

D3.8 records that `cards.json` is a validated intermediate with **no** byte check, because
`report.py` cannot regenerate it, and that `validate_card_set`'s totality stands in place of one.
After T3.5, `run.py` regenerates it under `make reproduce` and the byte check exists.

Both guards stay. The crosswalk catches a card that disagrees with its sources on any machine and
in any working tree; the byte check catches only what a full canonical rebuild would produce. They
fail on different things and neither subsumes the other. The DECISIONS entry records the change to
D3.8's stated limitation rather than leaving it reading as still true.

## 5. Network, and the honest failure modes

T3.5 is the first task permitted to run `fetch.py` against upstream. Every prior task was forbidden
from it, and that prohibition ends here by design.

**The digests are the safety net, not the network.** A fetch that returns different bytes fails
`compare_manifest` loudly. A fetch that changes a committed digest is a **finding, not a fix**: it
means upstream moved under a pinned revision, which is a fact about the world worth recording, and
the manifest must not be re-bootstrapped to make the failure go away.

Three failure modes that are not defects in this repository, and which the gate must report
distinguishably rather than as "reproduction failed":

- **Upstream unreachable.** `fetch_bytes` returns `None` on error. A network outage must read as
  an infrastructure failure, not as a reproduction mismatch.
- **Upstream moved.** Digests differ. This is the finding above.
- **Rate limiting.** Distinct from an outage in cause and in what to do about it.

Reproduction depending on a live network is a real cost, and this spec accepts it because the
alternative, vendoring upstream artifacts into the repository, would make the reproduction claim
circular: it would prove the pipeline is deterministic while proving nothing about whether the
committed results came from the upstream data they claim to.

## 6. The CI gate

The "reproduce is a loud failure at this phase" step is deleted and replaced by:

```yaml
      - name: reproduce
        run: make reproduce

      - name: worktree is clean after reproduction
        run: |
          if [ -n "$(git status --porcelain)" ]; then
            git status --porcelain
            git diff
            exit 1
          fi
```

The second step is deliberately redundant with `check_reproduction.py`. The script can be wrong;
`git status` in the job cannot be wrong in the same way, and the two failing together is worth
more than either alone. It prints the diff on failure, because a byte mismatch with no diff shown
is a report that cannot be acted on.

**CI is the only place a reproduction verdict is established.** The job already pins the runner
image and the patch version and records the environment; T3.5 adds nothing to that and relies on
it.

## 7. Tests

Every control shown failing before its guard exists.

- **The checker catches each artifact.** For each of the five plus the README, dirty exactly that
  one in a sandbox and assert the checker names it and exits non-zero.
- **A new undeclared artifact fails.** Write an untracked non-ignored file and assert the checker
  fails, so a stage that starts emitting something nobody declared is caught.
- **A gitignored file does not fail it.** `labels.csv` and `unevaluated.json` are rebuilt every run
  and must not dirty the verdict.
- **A missing artifact fails**, distinct from an unchanged one.
- **The non-canonical banner appears** off the canonical interpreter and platform, and its absence
  on the canonical one is asserted too, so the banner cannot become unconditional and meaningless.
- **The checker's exit code is the gate**, asserted directly rather than by parsing its output.
- **`reproduce` never passes `--bootstrap`**, asserted against the Makefile text, because a
  bootstrap inside reproduce would rewrite the manifest it is supposed to be checked against and
  turn every mismatch into a silent pass. This is the highest-value control in the task.

Not tested here, because it cannot be: that the canonical environment produces these exact bytes.
Only CI establishes that, and it does so by running, not by asserting.

## 8. What gets recorded

One DECISIONS entry: reproduction is real, what the target does, the change to D3.8's stated
limitation about `cards.json`, the decision not to vendor upstream and why, and the three network
failure modes that are infrastructure rather than reproduction defects.
